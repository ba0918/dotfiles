# Model Routing — モデル×タスク種別のルーティング表

2026-07-28 の実測に基づく配置。Opus 5 単独セッションの事後検証で、実測数値は 14/14 項目
完全一致（ハルシネーションゼロ）だった一方、handoff 未消費・issue 本文契約違反・依頼タスク
未着手が同時に起きた。分析力とプロトコル遵守がモデル内で分離しているため、
モデルにタスクを合わせるのではなく、席をモデルで固定する。

## ルーティング表

| タスク種別 | 担当 | 機構 |
|---|---|---|
| 対話・翻訳・清書・ルーティング・ゲート実行 | メインセッション（Opus 4.6/1m） | `/model` 既定 |
| 重大分岐の裁定・契約解釈・不可逆操作の事前判断・設計分岐 | judge（Fable 5） | `~/.claude/agents/judge.md` |
| read-only 調査・影響範囲特定・コード走査・指摘の裏取り | scout（Opus 5） | `~/.claude/agents/scout.md` |
| 実装・実装レビュー（網羅型） | Codex（GPT 系） | cross-model-rally / codex plugin |
| claim の実測裏取り（反証型レビューの一票） | scout（Opus 5） | 単独レビュワーにはしない |
| 実測実行（skill-regression fixture 実走 / eval executor） | Sonnet 5 | fixture の executor_tier に関わらず既定（2026-08-02 ユーザー指示、コスト優先）。Codex に流す場合は mini 系 or reasoning effort 最低段 |

## judge へのエスカレーション条件（これ以外で呼ぶのは浪費）

- 契約・仕様の解釈が 2 通り以上に割れた
- レビューの指摘同士が衝突した
- 不可逆操作（リリース・version bump・削除・force push・外部公開）の直前
- 設計分岐で選択肢の評価が拮抗している
- 定期監査（マージ済み成果物・登録 issue のガバチェック）

## 原則

- **Opus 5 に筆を持たせない**: 人間可読の成果物（issue / PR / コミット / 報告文）は
  すべてメインセッションが書く。Opus 5 の出力は構造化された生データとしてのみ受ける
- **委譲プロンプトに契約をインライン展開する**: スキル自動発火・常駐 rules・handoff を
  委譲先が読んでいる前提にしない
- **モデル指定は完全 ID のみ**（`claude-fable-5` / `claude-opus-5` 等）。`opus` エイリアスは
  複数世代が並存する現在、どの世代へ解決されるか未定義
- **judge に渡すのは裁定パックのみ**（背景 / 論点 / 選択肢 / 判断材料 / 不可逆性）。
  セッション全文を渡さない。なお人間向けの判断提示は、裁定パック（judge 向けの LLM 入力）とは
  別物として、ba0918-readability の基準で人が読める形に書く

## 運用ノート

- scout は純 read（Bash なし）。実測・再現の実行が要る調査は、メインセッションが
  コマンドを自分で実行するか、実測付き変種を検証してから追加する
- 配布するスキルの本体にモデル固定を書かない（プラットフォーム非依存にするため）。
  ルーティングはユーザースコープ側（この表）で持つ
- agent 定義と本表の文面調整は本番モデル（Opus 4.6）上で測る。別モデル上の感触で調整しない
- 表の行は実測で発火漏れ・誤配置が起きたときだけ追加する（憶測で肥大化させない）
