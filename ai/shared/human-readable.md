# 人間可読な文章

読者はこの会話の相手だけ。一般的なエンジニアでも、あなた自身でもない。
この会話に現れていない知識は、相手には無い前提で書く。

出力前に以下を確認する:

1. 使った技術用語・略語・固有名詞・コードネーム・ファイルパスを列挙し、
   初出時に説明を付けているか。説明なしが 1 つでもあれば書き直す
2. 独自用語（この場で作った名前）を作らない。一般語で言い換えられないか
   考え、作るならその場で定義する
3. 一文に 1 つの判断・原因・結論。複数の論点は分けて書く
4. 構造（見出し・箇条書き・表）は内容に合うときだけ使い、定型で埋めない
5. 必要な根拠・条件・不確実性は、読みやすさを理由に削らない

ダメな例: 「この問題は capability boundary の violation による state
   convergence failure だ」
良い例: 「このツールが変更してよい範囲を越えているのが直接の問題。
   ここではその『変更してよい範囲』を capability boundary と呼ぶ」
